# 精简的取舍

## 问题

原流程把课程、问答、练习、审查等活动都展示为显式 workstream 协调；重复的 inspect/sync/context、收尾步骤与状态说明容易挤占学习上下文。独立问答虽然有状态隔离，却仍需要人工搬运原问题语境。

## 本次调整

- 用户层面只强调“主线学习”和“独立问答”；其他模式按明确意图使用。
- 默认直接讲解与补齐基础，练习才采用分级提示；评估掌握时才收集实际证据。
- Skill 入口按意图路由，初始化只属于新课程发现。
- 增加只读 resume，复用已有上下文；普通消息不重复入口检查。
- 为独立问答冻结上下文包，并生成可以直接交给任务工具的启动消息。按章节复用问答 workstream，明确新任务时可另建。
- 保存最近相关讲解供后续提问引用；同值 checkpoint 不写入。
- 问题/答案存档与知识笔记分开，主线只同步有用的短结论。

## 保留的机制

保持 v2 schema、旧命令、锁和原子文件写入；不为交互精简强制迁移。保留路线确认、学习者掌握证据、源码质量判断及跨窗口所有权。

新问题包是不可变的历史快照，线程绑定只记录任务工具实际返回的 ID。自然语言意图由代理结合上下文判断，不用几个关键词在 Python 中伪装成可靠分类器。

## 没有选择的做法

不把 fork 作为默认：它可能复制无关历史，并遗漏当前未完成轮次。显式要求 fork 时，在分叉后补发精确问题包。

不自动创建每一次提问的任务：需要用户表达隔离意图。没有任务工具时退回保存上下文与短启动消息，不声称已操作侧边栏。

不删除旧协议或把状态全部塞回 progress.json：复杂性收进按需参考资料，保留并发写入与旧状态兼容。

## 发布结构

README 保持安装、自然语言入口和体验说明；协议、状态与验证细节各归对应文档。可编辑源与仓库发现副本同步，本机安装副本在验证后更新。
